## 1. Идея и зачем

**[Пётр]** Так должно выглядеть обучение в эпоху ИИ: текстовый и видеоконспект («доска»),
который человек достраивает под себя вместе с LLM. Любую сложную тему трудно уложить в голове,
поэтому хочется пересобрать материал под себя.

**[Пётр]** Принцип: «помоги, а не реши». Модель ведёт к пониманию и не думает за человека.

**[ресёрч]** Почему это важно: конспект, полностью собранный ИИ, учит хуже собственных заметок,
хотя нравится больше (Kreijkes et al., 2025, C&E); готовая выжимка ухудшает понимание у сильных
читателей (Etkin et al., 2025); ИИ без ограничений даёт −17% на экзамене без ИИ
(Bastani et al., 2025, PNAS). Поэтому ИИ строит справочный слой, а понимание пишет человек.

### Отличие

**[Пётр]** Исходная формула — гибрид NotebookLM и Notion. **[ресёрч]** Сама по себе она не
отличие: NotebookLM (с 16.07.2026 — Gemini Notebook) уже принимает YouTube и PDF, отвечает
с цитатами, ищет источники и делает учебные материалы; Notion правит выделенный текст агентом;
у ChatGPT есть Study Mode.

Отличие Course Companion:
- утверждение конспекта связано с моментом видео, слайдом и ячейкой кода одновременно;
- правки и объяснения не теряют источник: цепочка «источник → объяснение ИИ → моя версия»;
- приложение различает «видел», «разобрался с помощью» и «воспроизвёл сам»;
- **[DR]** интерактивное объяснение встроено в эту цепочку: источник → модель (сцена, лаба) →
  своё объяснение → применение, и прогон с выводом остаются в живом конспекте.

**[DR]** Интерактив сам по себе не отличие: интерактивные объяснения уже есть у ChatGPT
(03.2026, в GPT-6 — 10.2026) и Gemini (04.2026).

### Шаг 0 — до кода **[ревью]**

Одна пилотная лекция проходит путь руками или скриптом: источник → транскрипт с таймкодами →
воспроизведение в плеере со страницы с netcup. Проверить:
- какой плеер в уроке академии (YouTube или собственный) — **проверяет Пётр под аккаунтом**;
- загрузку транскрипта YouTube с netcup (возможна проверка «не бот»);
- ноутбук из `langchain-ai/deep-agents-from-scratch` открывается и разбирается.

Если путь не проходит — пилотной становится другая лекция с открытым YouTube. Код MVP-0
не начинается до прохождения шага 0.

## 6. Что входит в продукт

### 6.1 Лекция из своих материалов
1. Пользователь создаёт курс и добавляет лекцию: ссылка на YouTube плюс файлы
   (PDF-слайды, ноутбук `.ipynb`, текст/Markdown). Вариант Q1 «ссылки + файлы», без логина
   на платформах **[Пётр; спека v0.3]**. Запасной путь — загрузить файл субтитров или транскрипта.
2. Конвейер собирает лекцию: главы с таймкодами, транскрипт с поиском, конспект с привязкой к видео
   и слайдам, разбор кода из ноутбука. Каждое утверждение конспекта ссылается на источник
   (таймкод, слайд, ячейка).
3. Пользователь видит статус сборки и оценку стоимости до запуска. Ошибку отдельного источника
   приложение показывает явно, а не молча пропускает.
4. **[ревью]** Крайние случаи с явным сообщением: лекция 2–3 часа (сборка по частям), автосубтитры
   с ошибками в терминах (глоссарий курса для исправления), нет субтитров, видео удалено,
   скан-PDF без текста, ноутбук без выводов. В MVP-0 — только сообщение и запасной путь загрузки.

### 6.2 Курс из интернета по теме (этап 3)
**[Пётр]** Своих материалов нет, но хочется разобраться в теме.
1. Пользователь пишет тему и, по желанию, свой уровень и цель.
2. **[ресёрч]** Агент сначала показывает план и карту источников, а не готовый курс: для каждой
   лекции — цель, источники с датой и версией библиотеки, причина выбора, расхождения между
   источниками. Порядок доверия: официальная документация и release notes → оригинальная статья →
   университетский курс → доклад мейнтейнера → прочее.
3. **[ревью]** План показывает исключённые источники (логин, paywall) и почему.
4. Пользователь правит план и подтверждает. Лекции собираются тем же конвейером, что в 6.1.

**[моё]** Ограничения: одна тема — один курс, до 5–7 лекций, только общедоступные источники.

### 6.3 Учёба по лекции
Видео рядом с конспектом; главы, транскрипт и слайды в панели; переход к моменту видео из
конспекта и транскрипта; поиск по лекции; место, где остановился. Опираться на прототип 0.3:
режимы лекции, мобильная раскладка, чат в колонке. **[ресёрч]** По умолчанию «видео + конспект»,
транскрипт раскрывается по запросу; переход к видео по клику, без автопрокрутки видео за текстом.
Телефон — для повторения и проверок, сложная работа с кодом — на компьютере.

### 6.4 Чат по материалу
Чат в лекции отвечает по материалам текущего курса со ссылками на источники. Вопрос, заданный
из фрагмента, сохраняет привязку к нему. Ответ без опоры на материал помечается как общий ответ
модели.

### 6.5 Конспект в два слоя («доска») **[ресёрч]**
**Справочный слой** собирает ИИ: структура, утверждения со ссылками, разбор кода, глоссарий.
**Мой слой** пишет пользователь: «как я понял» в каждом разделе, свои примеры, вопросы, заметки.
ИИ может предложить помощь, но не заполняет «как я понял» за пользователя.

Действия по фрагменту, как в прототипе 0.2/0.3: «+» у абзаца и меню при выделении — «Спросить
в чате», «Объяснить проще», «Переписать».
- Объяснение или переписанный текст не затирает оригинал. Хранится цепочка «источник →
  объяснение ИИ → моя версия»; каждое звено можно открыть.
- **[ревью]** Происхождение видно у каждого блока: «из источника» / «объяснение ИИ» / «моя заметка».
- «Добавить в конспект» из ответа чата — пользователь видит место и текст перед сохранением;
  сохраняются ответ, ссылки на источники и пометка, что это ответ модели.
- Если пользователь правит утверждение так, что ссылка на источник может не подходить, ссылка
  получает статус «перепроверить».
- **[ревью]** Русский пересказ английского источника: показывать цитату оригинала рядом
  по запросу; выборочная проверка точности пересказа при сборке.

Минимальный 6.5 для MVP-0: «Объяснить проще», «Переписать», личная версия с возвратом к оригиналу,
поле «как я понял», пометки происхождения.

### 6.6 Правки и пересборка **[ревью]**
- Пересборка лекции создаёт новую редакцию, старая сохраняется.
- Личная правка привязана к фрагменту источника (таймкод/слайд/ячейка) и цитате, а не к
  внутреннему id блока. После пересборки правка переносится к тому же фрагменту.
- Правки, для которых место не нашлось, попадают в список «без места», а не пропадают.
- Лекция с личными правками автоматически не пересобирается (например, при смене модели) —
  только по действию пользователя.

### 6.7 Статусы прогресса **[ресёрч]**
Три статуса у раздела или понятия:
- **видел** — прочитал или посмотрел;
- **разобрался с помощью** — ответил после подсказок или после показа решения и закрепления;
- **воспроизвёл сам** — ответил или решил без подсказок.

Прогрессом курса считается только «воспроизвёл сам». **[ревью]** Вердикт о статусе ставит модель;
приложение хранит ответ пользователя и вердикт, пользователь может оспорить вердикт.

### 6.8 Практика по лекции (этап 1, домашка, вариант А)
**[Пётр: «оба»]** В конце раздела или лекции 3–5 заданий от агента: вопросы на понимание и,
где есть код, небольшие задачи. Пользователь отвечает, модель проверяет по правилу 6.10.

В MVP-0 — только короткая проверка «объясни без подсказки» для статуса «воспроизвёл сам».

### 6.9 «Моё задание» (этап 1, домашка, вариант Б)
**[Пётр: «оба»]** Пользователь вставляет или загружает своё задание в курс. Модель работает
как репетитор: выясняет, что уже понятно, ведёт по шагам, опирается на материалы курса и
проверяет решение пользователя. Сама решение не пишет, пока пользователь не нажал
«Показать решение» (6.10).

### 6.10 Правило ответа (общее для 6.8 и 6.9)
**[моё предложение, Пётр: «подходит»; уточнено ресёрчем и ревью]**
1. При ошибке или затруднении — лестница подсказок в 2–3 шага: намёк → ссылка на место
   в конспекте или таймкод → наводящий вопрос.
2. Кнопка «Показать решение» доступна всегда, с честным предупреждением: «так запомнишь хуже».
   Сначала она показывает следующий шаг решения, затем по повторному нажатию — полное решение.
3. После показа решения задача получает статус «решено с решением». Закрепление: объяснить
   ключевой шаг своими словами, затем похожая задача без подсказок.
4. Статус «воспроизвёл сам» — только после самостоятельного решения похожей задачи.

Обоснование: если отказывать в ответе совсем, взрослый пользователь уйдёт в ChatGPT.
Лучше дать ответ и превратить его в обучение. **[ресёрч]** Прямого исследования этой связки нет
(H2 — «проверить»); проверяем на себе по метрикам раздела 10.

### 6.11 Возврат
Библиотека курсов; продолжение с места остановки. **[DR]** Карточка возвращения отвечает за
несколько секунд: что я разбирал, где остановился, что осталось непонятным. «Продолжить разбор»
восстанавливает место, раскрытый эксперимент и черновик. **[ресёрч]** Главный экран — «продолжить с того,
что ещё не умею»: короткая проверка по понятиям без статуса «воспроизвёл сам» и вопросам,
оставшимся открытыми. Общих напоминаний «пора заниматься» и стриков нет: в крупных RCT по MOOC
напоминания и планирование дают нулевой или слабо отрицательный эффект.

### 6.12 Доступ (этап 2) **[ревью]**
- Вход по одноразовому приглашению и логину; утёкшая ссылка не даёт доступа.
- У каждого пользователя свои курсы; изоляция на сервере, как в разделе 08 спеки v0.3. Модель не
  может получить чужой курс через аргументы инструментов.
- Тесты изоляции — обязательное условие подключения знакомых.
- Материалы пользователя не видны другим, не публикуются без действия пользователя и не
  коммитятся в публичные репозитории.
- Бэкап данных, удаление аккаунта, экспорт своих курсов — до подключения знакомых.

### 6.13 Интерактивные объяснения **[DR]**
Три формата из одной модели: пошаговая сцена; мини-лаба с двумя прогонами (сравнение условий);
code-video из той же сцены.
- Режимы «Исследовать» (по умолчанию, без вопросов) и «Проверить себя»: прогноз перед
  содержательной развилкой → прогон → объяснение своими словами → новое условие. Прогноз не
  спрашивается перед каждым запуском.
- Прогон и вывод из «Проверить себя» сохраняются в конспект раздела как «моя заметка» и дают
  статус «воспроизвёл сам» по правилам 6.7.
- Генерация: спецификация сцены (состояние, шаги, ожидаемые числа) → проверенный движок →
  автоматические проверки ожидаемых чисел. Свободная генерация кода сцены моделью не идёт в
  интерфейс: в бенчмарке InteractScience лучший результат PPR — 16%.
- В MVP-0 — сцены пилотной лекции, собранные этим путём. Генерация по запросу пользователя тем же
  путём — этап решается после превью 0.4.
- У фрагмента три главных действия: «Объяснить», «Показать на примере», «Проверить себя»;
  остальное — во вторичном меню.

## 7. Недоверенный контент **[ревью]**

Видео, страницы, PDF, ноутбуки и ответы поиска — данные, а не инструкции.
- Конспектирование источника идёт без инструментов: модель только читает текст и пишет конспект.
- Источники передаются как данные в сообщении, не в системном промпте.
- Ссылки в конспекте и ответах — только на источники из утверждённого списка курса.
- Лимиты на шаги агента, токены, число страниц и длительность видео на одну сборку.
- Код из ноутбуков не исполняется (раздел 9).

## 8. Что не входит в MVP

- Заявки на генерацию в свободной форме («закажи анимацию»). **[DR]** Лаборатории, code-video
  и сцены — в MVP (6.13); ред. 2 их исключала.
- Импорт курсов с платформ за логином; одна ссылка на весь курс.
- Оплата, тарифы, публичная регистрация.
- Совместная работа, общие заметки, публичный экспорт курса.
- Полноценное интервальное повторение и межкурсовой тьютор (короткая проверка 6.11 остаётся).
- Делегирование работы Орио. **[моё]** У других пользователей Орио нет, поэтому агент живёт
  внутри приложения; Орио используется только как инструмент разработки.
  Это меняет направление спеки v0.3, где тяжёлую работу делал Орио.

## 9. Как делается

**[Пётр: «в целом верно»]**
- Бэкенд на Python; агент на Deep Agents / LangGraph там, где нужен цикл с инструментами (раздел 5).
- Фронтенд вырастает из прототипа 0.3/0.4 (статический HTML/CSS/JS); лаборатории и code-video
  остаются, заявки вырезаются **[DR]**. Фреймворк — решение строителя.
- Модели через API; **[Пётр]** конкретные модели подберём позже.
- Транскрипты YouTube — через имеющийся скрипт `~/scripts/yt_transcript.py` или его логику.
- Хостинг — сервер Петра: netcup VPS (Debian 13, Python 3.13; детали —
  `~/assistant-core/infrastructure/vps.md`).
- **[ревью]** Приложение работает от отдельного системного пользователя или в контейнере без доступа
  к `assistant-core`, ключам и секретам Орио.
- **[моё]** Проверка задач с кодом не запускает код пользователя: модель читает решение и оценивает
  его по материалам курса. Песочница для запуска кода — после MVP.

### Бюджет **[Пётр; уточнено ревью]**
- Расходы всех пользователей оплачивает Пётр, у каждого лимит (порядок — $5–10 в месяц
  на человека, точную сумму задать при подключении знакомых). Свои ключи API пользователи не вводят.
- Отдельный ключ API для приложения с лимитом расходов у провайдера.
- Серверный счётчик на **каждый** вызов модели: сборка, чат, «объяснить проще», проверка,
  репетитор. Перед дорогой операцией — резервирование суммы, как в спеке v0.3.
- Сборка лекции показывает оценку стоимости до запуска.

## 10. Метрики MVP-0 **[ресёрч]**

Для одного пользователя — три сигнала, а не продуктовая аналитика:
- дни с учёбой из 14 (порог раздела 3);
- доля понятий «воспроизвёл сам» при самопроверке через 2–3 дня;
- как часто решение открыто до собственной попытки (этап 1).

## 11. Ограничения

- **[Пётр]** Язык конспекта, чата и заданий — русский; ссылки и цитаты ведут на оригинал
  (обычно английский). Язык хранится как настройка курса, чтобы добавить английский без переделки.
- **Источники пилота (проверено 22.10.2026 Playwright с netcup, без логина):** страницы курсов
  LangChain Academy открываются, но уроки доступны только после бесплатной записи. Ноутбуки —
  в открытых GitHub-репозиториях `langchain-ai/langchain-academy` и
  `langchain-ai/deep-agents-from-scratch`. Плеер урока проверяется на шаге 0.
- Конспект не выдумывает: каждое утверждение опирается на источник.
- Публичный репозиторий спеки и репозиторий прототипа не являются репозиторием приложения.
  Для приложения нужен новый репозиторий.
